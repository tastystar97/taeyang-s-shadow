# Taeyang City Branch · Netlify 배포 안내

이 압축 파일은 플레이어 공용 UGN 인트라넷과 GM 관제실을 함께 포함합니다.

## 포함된 기능

- 공용 지부 대시보드와 페이즈 체크리스트
- 플레이어·관제실 로그인 성공 시 UGN 보안 단말 접속 애니메이션
- 태양시 정보망과 기존 플레이어용 HTML 문서 12종
- 지부장 전자서류 4종, 자동저장, 전자서명, 제출 잠금
- 본부 공문·의료기록·보호 서류·인수인계서 5종의 문서 내 직접 작성 및 서명
- 공문 체크 항목·회신 선택을 원문에서 클릭하고, 지부장 서명란을 누르면 최영호 전자서명 이미지가 입력됨
- 관제실 사진 등록과 플레이어용 증거물·현장사진 갤러리 및 원본 열람
- 기본 증거·현장 이미지 9종, 태양시 전경, COMMAND 대표 이미지
- 최영호 → 하은채 → 진태호 → 이세아 → 이태양 순서의 직원 명부와 사원증 원본 열람
- GM 관제실에서 페이즈·긴급 알림 변경 및 서류 승인·반려
- Netlify Blobs를 이용한 여러 기기 간 상태 저장

## 배포

이 ZIP은 정적 파일만 올리는 Drag & Drop용이 아니라 **Netlify가 빌드하는 소스 ZIP**입니다. 압축을 풀어 Git 저장소에 올린 뒤 Netlify의 **Import an existing project**로 연결하거나, Netlify CLI에서 프로젝트 폴더를 배포하세요. `netlify.toml`이 빌드와 Functions 위치를 자동으로 지정합니다.

Netlify 프로젝트의 Environment variables에 다음 값을 설정하세요.

- `BRANCH_ACCESS_CODE`: 지부장 코드. 반드시 설정하세요.
- `FIELD_ACCESS_CODE`: 현장요원 공용 코드. 반드시 설정하세요.
- `CONTROL_ACCESS_CODE`: `/control.html` 관제실 코드. 반드시 설정하세요.
- `SESSION_SECRET`: 충분히 긴 무작위 문자열. 반드시 설정하세요.

세 코드는 서로 달라야 합니다. 누락·중복 시 인증이 차단되며, 예전 `player` 세션은 재로그인해야 합니다. 코드 변경은 해당 역할의 기존 세션을 무효화합니다.

메인 플레이어 화면은 `/`이며 입력 코드로 지부장·현장요원을 구분합니다. GM 관제실은 `/control.html`입니다.

빌드 결과의 공개 경로는 `dist-netlify`입니다. `public`은 원본 소스 디렉터리이므로 직접 공개 배포하면 안 됩니다. 보관 문서·인사·증거·서명 원본은 Functions 번들에 포함되며 `/api/files`와 기존 URL의 보호 라우트를 통해 전달됩니다. Netlify 설정의 publish 경로와 included_files를 함께 유지하세요.

## 첫 배포 후 확인

1. 플레이어 화면에서 체크 항목 하나를 변경합니다.
2. 새 서류를 임시저장한 뒤 새로고침해 내용이 남아 있는지 확인합니다.
3. 문서보관소에서 `직접 작성 가능` 문서를 열고 문서 하단의 작성·서명란을 저장한 뒤 다른 기기에서도 같은 내용이 보이는지 확인합니다.
4. 관제실에서 테스트 사진을 등록하고 관제 목록과 원본을 확인합니다. 신규 사진은 비공개로 저장됩니다. 증거 공개 관리 UI는 M3에서 연결합니다.
5. 서류를 제출하고 `/control.html`에서 승인 대기 목록에 나타나는지 확인합니다.
6. 관제실에서 페이즈를 변경해 플레이어 화면의 체크리스트가 바뀌는지 확인합니다.

정적 서버에서는 인증·저장이 작동하지 않습니다. 서버 실패를 로컬 미리보기로 대체하지 않습니다. 실제 공용 저장은 Netlify Functions·Blobs 개발 환경에서 확인하세요.

M1 로컬 테스트는 메모리 저장소를 주입한 실제 Functions 핸들러로 수행했습니다. 운영 환경변수 등록·원격 상태 전환·실제 Netlify CDN 라우팅·배포는 별도로 확인해야 합니다.

## 인사기록 관리 (M2)

GM 로그인 후 인사기록 메뉴 또는 `/control.html#personnel`에서 등록·수정합니다. 이름·사번·보직·부서 검색, 공개 대상 필터, 표시 순서 변경을 지원합니다. 사번은 중복할 수 없습니다.

사원증 이미지와 인사 원문을 각각 하나씩 첨부합니다. 원문은 HTML·PDF·JPG/PNG/WEBP/GIF, 파일당 4MiB 이하입니다. HTML은 UTF-8 단일 파일을 사용하고 이미지는 base64로 포함하세요. 외부·상대경로 자산은 거절하며 스크립트와 입력폼은 제거합니다. 첨부는 미리보기 또는 새 탭으로 확인하고 인사정보 저장을 눌러 반영합니다. 첨부 해제도 저장해야 적용됩니다.

새 기록은 비공개입니다. 공개 대상에서 한 건씩 바꾸거나 목록 체크박스로 항목을 골라 지부장·현장요원에게 일괄 공개·비공개하세요. 정보 수정·첨부 교체·순서 변경은 공개 대상을 바꾸지 않습니다.

파일은 site-scoped Netlify Blobs `taeyang-city-files`의 `meta/`와 `body/`에 저장합니다. 임시 파일은 24시간 내 저장 가능하며, GM 화면 진입 시 25시간이 지난 미참조 첨부를 최대 100개 메타정보 범위에서 정리합니다. 배포·백업 시 공유 상태 저장소와 이 파일 저장소를 함께 보존하세요.

M2 로컬 테스트는 메모리 저장소를 사용했습니다. 실제 Blobs에서 등록 후 다른 단말 열람, 비공개 원본 차단, 운영 브라우저 PDF 표시를 배포 검증에 포함하세요.

## 아카이브 관리 (M3)

GM 로그인 후 아카이브 메뉴 또는 `/control.html#archive`에서 문서를 등록합니다. 문서명·문서번호·분류는 필수이며 요약과 표시용 보안등급을 입력할 수 있습니다. 문서번호는 중복할 수 없습니다. 원문은 HTML·PDF·이미지 한 개, 최대 4MiB이며 M2와 같은 HTML 조건을 적용합니다.

파일을 선택하고 미리보기로 확인한 뒤 비공개로 등록하세요. 공개 대상에서 한 건씩 바꾸거나 목록 체크박스로 고른 문서만 지부장·현장요원에게 일괄 공개·비공개합니다. CITY NET의 로케이션·역사 문서는 두 플레이어 역할에 전체 공개로 고정됩니다. 파일 교체는 문서 ID와 공개 대상, 관련 알림·사건철 연결을 유지합니다. 비공개 전환은 이후 원본 요청을 차단하며, 플레이어의 열린 창은 다음 상태 동기화 때 닫힙니다.

기존 작성·서명 가능한 5종은 앱 관리 서식입니다. 관제에서 작성 내용을 읽고 문서정보·공개 대상을 관리할 수 있으며 원본 교체는 지원하지 않습니다. 지부장의 기존 작성·서명은 유지합니다. 일반 기본 문서와 새 업로드 문서는 파일 교체를 지원합니다.

원격 검증 시 테스트 문서를 비공개 등록한 뒤 다른 단말에서 한 건 공개·열람·교체·비공개를 확인하고, 기존 5종의 작성 내용과 서명을 대조하세요. M3도 상태와 파일 저장소를 실제 원격 환경에 쓰지 않고 로컬 메모리 저장소로 검증했습니다.

## 전자결재 열람 (M4a)

관제의 전자결재 메뉴 또는 `/control.html#workflow`에서 승인 대기 서류를 확인합니다. 상태·서식 필터와 제목·문서 ID 검색을 사용할 수 있습니다. 서류 열기에서 본문, 추가 보관 항목, 서명, 작성·수정 시각, 반려 사유를 확인하세요. 열람은 저장하지 않습니다.

GM 결재 대상인 제출 서류만 뷰어에서 승인·반려할 수 있으며 반려 사유를 입력해야 합니다. 다른 단말이 상태를 변경한 경우 최신 서류 다시 확인을 누르고 재검토합니다. 현장 보고서 작성·제출과 지부장 결재는 M6 통합 단계에서 구현했습니다.

## 사건철·플레이어 미리보기 (M5)

GM 로그인 후 사건철 메뉴 또는 `/control.html#cases`에서 사건철을 등록합니다. 인물·아카이브·증거·전자결재를 연결하고 순서를 정한 뒤 저장하세요. 신규 사건철은 비공개입니다. 단건 공개 또는 목록 체크박스 일괄 공개를 사용할 수 있지만, 사건철을 공개해도 연결 자료는 자동 공개되지 않습니다.

사건철에서 자료 연결 해제나 사건철 삭제를 해도 원본 자료는 유지됩니다. 연결 대상 원본이 삭제된 경우 관제 목록에서 해당 연결을 해제하세요. GM 전용 메모는 플레이어 상태에 포함되지 않습니다.

관제 상단의 지부장 미리보기와 현장요원 미리보기는 선택 역할에 실제로 공개된 상태와 원본만 보여줍니다. 미리보기는 읽기 전용이며 관제로 돌아가도 기존 메뉴·검색·입력값을 유지합니다. 운영 검증에서는 실제 지부장·현장요원 코드로 접속한 화면과 목록·건수·원본 접근을 각각 비교하세요.

실제 Netlify 환경에서 사건철과 단서 A·B·C를 준비하고 사건철→A→B 순서로 공개하며 매 단계의 목록·원문 권한을 확인하세요. 체크박스 일괄 공개를 쓸 때는 선택 목록을 다시 확인하고, C의 제목·건수·자리 표시는 공개 전까지 없어야 합니다.

## 현장 보고·UI 통합 (M6)

현장요원은 WORKFLOW의 공용 보고서함에서 현장 상황 보고서를 작성·임시저장·제출합니다. 보고 제목·보고자·현장 위치·확인 일시·확인 내용은 필수입니다. 제출본은 잠기며 지부장의 수신 알림과 결재 목록에 나타납니다.

지부장은 제출 버전을 확인한 뒤 승인하거나 사유를 적어 반려합니다. 반려 뒤 현장요원이 수정하는 동안 지부장에게는 직전 제출본만 보이며, 재제출하면 버전이 증가합니다. GM은 관제 전자결재에서 초안을 포함한 전체 기록을 열람·삭제할 수 있지만 지부장 대신 결재할 수 없습니다. 제출과 결재는 사건철·아카이브·증거의 일반 공개 대상을 바꾸지 않습니다.

관제의 증거물 메뉴에서 단건 공개 대상을 지정하거나 체크박스로 고른 기록을 일괄 공개·비공개합니다. 체크하지 않은 증거와 사건철 연결 자료는 함께 바뀌지 않습니다. 관제 알림의 사건철 목적지도 지원합니다.

운영 반영 순서와 코드·상태·파일을 함께 되돌리는 절차는 [docs/M6_RELEASE_CHECKLIST.md](docs/M6_RELEASE_CHECKLIST.md)를 따르세요. 2026-09-06 운영 반영 결과, 백업 위치, 검증 기준 배포 ID와 검증 내역은 [docs/M7_PRODUCTION_ROLLOUT.md](docs/M7_PRODUCTION_ROLLOUT.md)에 기록했습니다.
