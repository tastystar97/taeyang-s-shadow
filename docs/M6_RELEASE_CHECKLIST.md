# M6 운영 반영·복구 체크리스트

이 문서는 로컬 검증이 끝난 배포 후보를 Netlify 운영 환경에 반영할 때 사용하는 절차야. 로컬 메모리 저장소 검증 결과를 운영 Blobs 검증으로 대신하지 않아.

## 반영 전

1. `BRANCH_ACCESS_CODE`, `FIELD_ACCESS_CODE`, `CONTROL_ACCESS_CODE`, `SESSION_SECRET`이 모두 설정되고 세 코드가 서로 다른지 확인해.
2. 현재 운영 배포 식별자와 Git 커밋을 기록해.
3. site-scoped `taeyang-city-branch` 저장소의 공유 상태 원본과 ETag를 백업해.
4. `taeyang-city-files`, `taeyang-city-evidence` 저장소의 객체 목록·메타정보·본문을 함께 백업해.
5. 상태의 인사·아카이브·증거·서류·사건철 수, ID, 서류 본문·서명·결재 상태와 파일 SHA-256을 전환 매니페스트에 기록해.
6. 새 자료 등록·결재·체크리스트 변경을 잠시 중단하고 마지막 상태와 파일 차이를 한 번 더 백업해.

## 배포와 확인

1. `pnpm test`와 `pnpm build`가 통과한 커밋만 배포 후보로 사용해.
2. 먼저 Netlify Deploy Preview에 배포하고 세 역할 코드로 각각 로그인해.
3. 관제에서 비공개 테스트 자료를 한 건 등록하고 지부장 또는 현장요원 한 역할에만 공개해. 다른 역할의 목록·원본 URL에서 차단되는지 확인해.
4. 사건철과 단서 A·B·C를 준비하고 사건철→A→B 순서로 한 건씩 공개해. C의 제목·건수·자리 표시가 나타나지 않는지 확인해.
5. 현장요원 보고서 작성·제출→지부장 반려→수정본 재제출→지부장 승인→GM 열람을 확인해. GM 대행 결재와 지부장의 보고서 본문 수정이 거절되는지 확인해.
6. 관제의 지부장·현장요원 미리보기와 실제 역할 화면의 목록·건수·원본 접근을 비교해.
7. 기존 인사 5명, 아카이브 12종, 정적 증거 9종, 지부장 전자서식 4종, 편집 문서 5종의 ID·본문·서명·해시를 전환 전 매니페스트와 대조해.
8. 데스크톱과 모바일에서 로그인, 검색, 업로드, 공개, 원문 열기, 결재, 로그아웃을 확인한 뒤 운영 배포로 승격해.

## 복구

1. 쓰기를 다시 중단하고 새 버전에서 생성·변경된 상태와 파일을 별도 백업해 유실을 막아.
2. 이전 운영 배포로 코드를 되돌려.
3. 이전 코드가 새 스키마를 처리하지 못하거나 데이터 손상이 확인되면 공유 상태와 두 파일 저장소를 같은 백업 시점으로 함께 복원해.
4. 복원 전에 현재 ETag와 백업 당시 ETag가 다르면 무조건 덮어쓰지 말고 변경 내역을 먼저 합쳐.
5. 세 역할 로그인, 기존 문서 원본, 체크리스트, 전자서명, 공개 범위를 다시 확인한 뒤 쓰기를 재개해.

운영 검증이 끝날 때까지 로컬 결과는 “배포 후보” 상태야. 원격 백업과 실제 Netlify Blobs·CDN 확인을 마친 시점에만 운영 반영 완료로 기록해.
