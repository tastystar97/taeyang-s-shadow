# 0단계 설계서 — 태양시 지부 인트라넷

작성일: 2026-09-05 · 버전: M0 v0.1
상태: 요구사항 확정·구현 계약 작성, 화면 시안은 검토용 초안
대상: taeyang-city-branch-netlify

이 문서는 1단계 구현에 사용할 설계야. 앱 기능·서버 코드·운영 데이터 변경을 뜻하지 않아. 코드 현황은 로컬 소스로 확인했고, 화면 참고는 로컬 정적 미리보기로 확인했어. 화면 시안 속 날짜·본문·첨부명·공개 상태는 배치 확인용 예시이며 실제 시나리오 데이터로 이관하지 않아.

## 1. 주인이 확정한 요구사항

| 항목 | 확정 내용 |
| --- | --- |
| 현장요원 접속 | 현장요원 전체가 공용 코드 1개를 사용해. |
| 지부장·GM 접속 | 지부장과 GM은 현장요원과 별도 코드를 유지해. |
| 현장요원 업무 | 공개 자료·사건철·작전 정보 열람과 현장 보고서 작성·제출을 지원해. |
| 현장 보고 결재 | 지부장이 검토·승인·반려하고, GM은 열람·관리해. |
| 업로드 | 인사·아카이브는 HTML·PDF·이미지를 지원해. |
| 공개 방식 | GM이 자료 하나씩 수동 공개해. 일괄·예약·자동 공개는 없어. |
| 사건철 | 자료를 연결해 정리하지만 연결하거나 사건철을 공개해도 자료 공개 범위는 바뀌지 않아. |
| 플레이어 미리보기 | GM이 지부장·현장요원 시점을 읽기 전용으로 확인해. |
| 기존 결재 | 기존 지부장 작성 서류는 계속 GM이 결재해. |

공용 코드로는 접속한 사람을 개인별로 증명할 수 없어. 현장 보고서는 현장요원 공용 서류함에 보이고, 보고자 이름은 작성자가 입력한 이름으로 기록해. 개인별 비밀 초안·개인별 수정 권한·개인별 접속 폐기는 이번 범위가 아니야.

설계 기본값: 기존 자료의 지부장 접근은 유지하고 현장요원에게는 처음부터 일괄 공개하지 않아. GM이 자료별로 공개해. 새 인사·문서·증거·사건철은 관제 전용으로 생성해.

## 2. 역할과 권한

| 동작 | 현장요원 agent | 지부장 director | 관제 gm |
| --- | --- | --- | --- |
| 일반 자료·사건철 열람 | 해당 역할에 공개된 자료 | 해당 역할에 공개된 자료 | 전체 |
| 인사·아카이브·증거 업로드·수정 | 불가 | 불가 | 가능 |
| 자료 한 건 공개·비공개 | 불가 | 불가 | 가능 |
| 사건철 생성·연결·정렬 | 불가 | 불가 | 가능 |
| 현장 보고 초안 작성·수정·삭제 | 공용함의 DRAFT·RETURNED | 불가 | 본문 대필 불가, 관리 삭제 가능 |
| 현장 보고 제출 | 가능 | 불가 | 불가 |
| 현장 보고 수신함 열람 | 공용함의 자체 보고 | 제출된 보고와 처리 이력 | 초안 포함 전체 |
| 현장 보고 승인·반려 | 불가 | SUBMITTED만 | 결재 대행 불가 |
| 기존 지부장 서류 작성·서명·제출 | 불가 | 가능 | 본문 대필 불가 |
| 기존 지부장 서류 승인·반려 | 불가 | 불가 | SUBMITTED만 |
| 보관 문서 5종 작성·서명 | 불가 | 기존 동작 유지 | 읽기 전용 |
| 체크리스트 변경 | 읽기 전용 | 가능 | 가능 |
| 페이즈·알림 운영 | 불가 | 불가 | 가능 |
| 플레이어 시점 미리보기 | 불가 | 불가 | 두 역할 중 선택, 읽기 전용 |

GM 관리 삭제는 기존 관제 서류 삭제 권한을 이어받되 대상을 확인하고 활동 기록을 남겨. GM이라는 이유로 작성자나 결재자를 사칭해 본문·서명·승인 결과를 바꾸지는 않아.

## 3. 접속 계약

- 지부장 코드는 기존 `BRANCH_ACCESS_CODE`, 현장요원 코드는 새 `FIELD_ACCESS_CODE`, GM 코드는 기존 `CONTROL_ACCESS_CODE`를 사용해.
- 플레이어 입구는 코드만 받고 서버가 지부장 또는 현장요원 코드를 판별해. 관제 입구는 GM 코드를 검사해. 클라이언트가 전송한 역할명만으로 권한을 부여하지 않아.
- 세 코드가 중복되거나 필수 값이 누락되면 설정 오류로 처리해. 코드 값 자체는 문서·로그·브라우저 번들에 저장하지 않아.
- 서명된 세션은 `role`, 만료시각, 세션 버전을 포함해. 기존 `player` 세션은 새 역할로 무조건 승격하지 않고 재로그인하게 해.
- 코드 변경 시 해당 역할의 이전 세션이 무효화되도록 코드와 연동한 버전 검증을 둬. 코드 원문이나 비교 가능한 단순 코드 해시는 응답하지 않아.
- 기존 12시간 세션을 기본으로 유지해. 로그아웃하면 세션과 역할별 화면 캐시를 정리해.
- 운영 인증 실패나 서버 장애를 로컬 공개 미리보기로 전환하지 않아. 로컬 데모는 명시적인 개발 모드에서만 사용해.

## 4. 두 개의 결재 흐름

| 종류 | 작성·제출 | 수신·결재 | GM |
| --- | --- | --- | --- |
| 기존 지부장 서류 4종 | director | gm | 열람·결재·관리 |
| 새 현장 보고서 field-report | agent | director | 열람·관리 |

상태 흐름은 `DRAFT → SUBMITTED → APPROVED`, 반려 시 `SUBMITTED → RETURNED → 재작성 → SUBMITTED`로 통일해.

- 초안·반려 상태에서만 작성 역할이 내용을 수정하거나 제출해. 제출·승인 상태의 본문은 잠가.
- 현장 보고가 제출되면 지부장 수신함에 전달하고 그 보고를 여는 업무 알림을 생성해. GM도 확인할 수 있어.
- 제출에 따른 지정 수신함 전달은 자료의 일반 공개와 구분해. 승인·반려해도 아카이브나 사건철의 공개 대상은 바뀌지 않아.
- 지부장은 현장 보고의 제출본을 검토해. 반려 후 작성자가 수정 중인 초안과 직전 제출본을 혼동하지 않도록 마지막 제출본·제출 시각·제출 버전을 남겨.
- 승인·반려 요청은 서류 ID와 검토한 버전을 보내. 서버는 종류·결재자 역할·SUBMITTED 상태·버전을 다시 검사해.
- 반려 사유는 현장 보고에서 필수로 해. 승인·반려 주체와 처리 시각을 기록해.
- 현장 보고 제출은 지부장의 기존 체크리스트를 자동 완료하지 않아. 기존 지부장 서류의 체크리스트 연동만 유지해.
- 임의 템플릿이나 숨겨진 필드를 보내 기존 지부장 서류로 바꾸거나 결재자를 바꿀 수 없게 서버가 종류와 역할을 결정해.

### 현장 보고서 1차 서식

| 항목 | 필수 | 입력 |
| --- | --- | --- |
| 보고 제목 | 예 | 짧은 제목 |
| 보고자 | 예 | 작성자가 입력한 이름 |
| 관련 사건 | 아니오 | 현장요원에게 공개된 사건철 중 선택 |
| 현장 위치 | 예 | 텍스트 |
| 현장 확인 일시 | 예 | 날짜·시각 |
| 확인 내용 | 예 | 여러 줄 본문 |
| 위험·피해 상황 | 아니오 | 여러 줄 본문 |
| 지원 요청·후속 조치 | 아니오 | 여러 줄 본문 |
| 관련 자료 | 아니오 | 자신에게 허용된 인사·문서·증거 참조 |

보고서에 새 파일을 올리는 기능은 1차에 추가하지 않고 이미 공개된 자료를 연결해. 임시저장과 `지부장에게 제출`을 분리해. 지부장 서명 이미지를 현장 보고서 작성에 사용하지 않아. 공용함에서 동시에 편집하면 충돌을 안내하고 다른 작성자의 내용을 덮어쓰지 않아.

## 5. 공개·사건철 계약

일반 자료의 공개 정보는 `audience: [] | ["director"] | ["agent"] | ["director","agent"]`로 표현해. 빈 배열은 관제 전용이고, GM 접근은 서버 권한에서 처리해. 세계관 표시용 `security`와 실제 공개 권한은 별도야.

- 생성·업로드·사건철 연결·정렬·페이즈 변경·결재 처리로 `audience`를 자동 확대하지 않아.
- 공개 API는 자료 종류·단일 ID·새 공개 대상·검토 버전만 받아. 여러 ID, 와일드카드, 연결 자료 전파 옵션은 거절해.
- 사건철 자체가 보이고 연결 자료도 해당 역할에게 일반 공개된 경우에만 사건철에서 보여줘.
- 결재 서류의 작성자·수신자 권한은 업무 서류함에서 사용해. 사건철에서는 그 권한만으로 자동 노출하지 않고 GM이 지정한 일반 공개 대상까지 확인해.
- 숨겨진 자료의 제목·ID·썸네일·파일명·건수·자리 표시·원본 링크·GM 메모는 응답하지 않아. 검색과 탭 건수도 필터링한 자료만 계산해.
- 단일 자료 공개 상태는 모든 사건철·일반 목록에서 동일해. 한 사건에서만 따로 공개하는 기능은 이번 범위에 넣지 않아.
- 사건철 연결은 `{type, id, order}`로 표현해. 같은 자료를 여러 사건에 연결할 수 있지만 같은 사건 내 중복 연결은 막아.
- 사건철 삭제·연결 해제는 원본 자료를 지우지 않아. 원본이 삭제되면 플레이어의 끊어진 링크는 제외하고 관제에 정리를 안내해.
- 기존 `caseCode`는 표시 정보로 보존해. 코드 문자열이 비슷하다고 사건철이나 연결을 임의 생성하지 않아.

## 6. API와 미리보기 경계

기존 Netlify Functions와 ES 모듈 구조를 유지해. 아래 신규 액션명과 파일 경로는 1단계 구현 계약 초안이고 아직 구현되지 않았어.

| 경로·동작 | 계약 |
| --- | --- |
| `POST /api/auth` | 접속코드 검증, 서버에서 역할 결정 |
| `GET /api/auth` | 현재 실제 역할·인증 상태 응답 |
| `DELETE /api/auth` | 로그아웃 |
| `GET /api/state` | 실제 세션 역할로 필터링한 상태 |
| `PATCH /api/state` | 액션별 역할·자료 종류·버전 검사 |
| `GET /api/files?id=...` | 자료 권한과 파일 참조를 확인한 원본 열람 |
| 파일 등록·교체 경로 | GM만 접근, 파일 저장과 메타정보 갱신 분리 |
| `GET /api/preview?role=director|agent` | GM 인증 후 선택 역할로 필터링한 상태 |
| 미리보기 원본 열람 경로 | GM 인증 후 같은 대상 역할로 자료·파일 재검사 |
| 미리보기 경로의 POST·PATCH·DELETE | 405, 저장·읽음 표시를 포함한 쓰기 없음 |

새 액션군은 `save-field-report`, `submit-field-report`, `delete-field-report`, `approve-field-report`, `return-field-report`, 사건철 관리, 단건 `set-resource-audience`로 나눠. 기존 `save-form` 등은 지부장 서류 전용으로 유지해.

미리보기는 GM의 실제 세션을 플레이어 세션으로 바꾸지 않아. 미리보기 전용 클라이언트는 모든 상태·파일 요청을 읽기 전용 경로로 보내고, 새 탭·서식 뷰어에도 같은 대상 역할을 이어줘. 일반 상태 API는 사용자가 보낸 `viewerRole`을 신뢰하지 않아.

버튼을 숨기는 것뿐 아니라 미리보기 API의 쓰기 거절을 검증해. 서류 열람 시 자동저장, `mark-document-read`, 체크리스트 갱신도 실행하지 않아. 돌아오면 관제의 선택 메뉴·검색·입력 중 폼을 유지해.

성공 응답뿐 아니라 409 충돌의 최신 상태·오류·알림·활동 기록도 필터링해. 제한 자료를 public 번들이나 로컬 기본 상태로 다시 전달하지 않아.

## 7. 저장 구조와 전환

| 엔터티 | 보존·추가할 내용 |
| --- | --- |
| 공유 상태 | 기존 revision과 데이터 유지, schemaVersion 추가 |
| personnel | 기존 ID·사번·이름·순서·본문 보존, audience와 파일 참조 추가 |
| documents | 기존 ID·URL 대응·분류·표시등급·editable 보존, audience·파일 참조·sourceKind 추가 |
| evidence | 정적 9종과 기존 업로드를 ID로 병합, caseCode 보존, audience 추가 |
| cases | 고유 ID·사건번호·제목·요약·진행 상태·GM 메모·audience·links |
| forms | 기존 4종은 kind=director-form, authorRole=director, reviewerRole=gm으로 보완 |
| 현장 보고 | kind=field-report, authorRole=agent, reviewerRole=director, 보고자·내용·참조·마지막 제출본·처리 기록 |
| archiveEntries | 기존 편집 5종의 ID·내용·서명·수정시각 보존 |
| readReceipts | 기존 NEW/RELEASED 의미와 구분한 역할별 열람 상태 |
| files | 고유 파일 ID·자료 참조·원래 이름·MIME·바이트 수·해시·저장 키 |

기존 `NEW` / `RELEASED`는 열람 상태로 쓰이고 있어서 실제 공개 여부로 변환하지 않아. 새 audience가 없는 기존 자료는 이전 작업에서 지부장 접근을 유지하도록 채우고 현장요원은 별도 공개해.

전환은 원본 백업 → 검증용 복사본 전환 → ID·본문·서명·파일 해시 대조 → 재실행 중복 검사 → 복구 연습 → 운영 반영 순서야. 기존 상태가 있으면 먼저 원본을 읽고 누락 필드와 seed만 추가해. 같은 ID의 기존 기록·공개 설정을 초기값으로 덮어쓰지 않아. 같은 ID가 충돌하는 자료는 조용히 합치지 않고 전환을 중단하고 검토해.

보호할 기존 정적 자료는 인증 경로로 제공해. 이전 URL은 인증된 제공 경로로 매핑하고 공개 파일 사본은 배포 경로에서 제거해. 작성형 HTML 5종과 읽기 전용 업로드 HTML은 제공 방식을 나눠. 기존 작성형 문서의 편집 스크립트·내부 이미지 상대경로·서명을 함께 점검해.

파일은 버전별 새 키에 저장하고, 공유 상태가 그 키를 참조하게 바꾸는 데 성공한 뒤 이전 파일을 정리해. ETag 조건부 쓰기로 메타정보 충돌을 확인하고, 실패한 파일은 정리 대상으로 기록해. 파일 삭제를 먼저 해서 기존 참조가 깨지게 하지 않아.

실제 원격 데이터 수량·운영 백업은 아직 확인·실행하지 않았어. 로컬 인벤토리는 DATA_INVENTORY.md를 기준으로 하고, 운영 반영 전 원격 업로드·서류·기록을 추가 대조해야 해.

### 엔터티별 전환과 실패 처리

| 대상 | 식별 기준 | 기존 공개값이 없을 때 | 충돌·실패 처리 |
| --- | --- | --- | --- |
| 인사 | id가 기본, employeeId는 중복 검사용 | 기존 5명은 director | 같은 사번에 다른 ID가 있으면 자동 병합하지 않고 검토해. |
| 아카이브 | 기존 문서 id | 기존 문서는 director | 기존 문서 원문·편집 기록을 보존하고, 정체가 다른 동일 ID는 중단해. |
| 증거 | evidence id와 기존 출처 참조 | 기존 정적·업로드 자료는 director | 업로드 ID가 정적 seed ID와 우연히 같으면 덮어쓰거나 임의 재번호하지 않고 중단해. 같은 자료의 수정본임이 확인될 때만 기존 기록을 유지해. |
| 기존 forms | form id와 기존 template | audience는 빈 배열 | 업무 서류함의 director 작성자·gm 결재자 접근을 유지해. 일반 공개를 새로 부여하지 않아. |
| 새 field-report | 서버가 생성한 form id | audience는 빈 배열 | agent 작성자·제출 후 director 수신 접근을 별도로 적용해. |
| cases | case id | 새 사건철은 빈 배열 | 기존 사건철 seed는 없어. 사건명·caseCode로 임의 생성하지 않아. |
| archiveEntries | 기존 문서 id | 소속 문서 권한을 따라 | 내용·서명은 원형을 보존하고 대상 문서가 없으면 중단해. |

여기서 '공개값이 없다'는 필드가 존재하지 않는 이전 스키마만 뜻해. 이미 저장된 `audience: []`는 의도적인 비공개이므로 director로 채우지 않아. 기존 `NEW`·`RELEASED` 열람값은 읽음 상태 전환에만 사용해.

전환 매니페스트에는 엔터티 종류·원래 ID·출처·원본 해시·새 파일 키·검증 결과를 남겨. 전체 메타정보는 메모리의 검증용 복사본에서 준비하고, 파일 존재·형식·해시·문서 내부 참조가 모두 통과한 뒤 원래 ETag를 조건으로 한 번 반영해. 데이터가 중간에 바뀌면 새 원본에서 다시 준비하고 기존 스냅샷을 무조건 덮어쓰지 않아.

어느 필수 파일이 누락되거나 검증에 실패하면 스키마 버전·참조를 전환하지 않고 중단해. 구버전 서비스의 원본은 보존하되, 새 역할을 열어놓고 공개 정적 경로로 우회하는 임시 처리는 하지 않아. 새 역할 운영은 보호 경로 검증까지 끝난 뒤 시작해.

파일 교체는 새 키 저장·읽기 검증 → ETag 조건부 메타정보 반영 → 이전 키 보존·정리 순서야. 반영 실패 시 기존 참조는 유지해. 응답이 끊겨 성공 여부가 불명확하면 현재 참조를 다시 읽고 확인해. 이미 반영된 새 파일을 오류로 판단해 삭제하거나 다른 단말의 변경을 과거 스냅샷으로 덮어쓰지 않아.


## 8. 업로드 형식과 범위

- 인사 원문·아카이브: HTML, PDF, JPG·PNG·WEBP·GIF. 기존 증거 이미지는 기존 형식을 유지해.
- 초안 파일 상한은 파일당 4 MiB이고 multipart 전체 크기도 제한해. 최종 상한은 Netlify 실제 업로드·다운로드 경계 검사에서 확정해.
- 확장자와 브라우저 MIME만 믿지 않고 실제 파일 형식을 확인해. 파일명은 표시용으로만 사용하고 저장 키는 서버가 생성해.
- HTML은 한 파일로 열 수 있는 원문을 기준으로 받아. 상대경로 이미지·CSS가 필요하면 저장 전에 누락을 안내해. ZIP과 폴더 업로드는 1차 범위 밖이야.
- 업로드 HTML의 스크립트·폼·위험한 삽입 요소·외부 통신을 제한하고 iframe 및 새 탭 원문에도 같은 격리를 적용해. 정화 후 실제 표시를 GM이 미리 확인해.
- 기존 편집 HTML 5종은 앱 소유 서식으로 관리해서 기존 입력·서명을 유지해. 업로드한 HTML이 자동으로 입력형 서식으로 승격되지는 않아.
- 파일 교체도 기존 문서 ID를 유지해. 업로드와 공개는 별도 동작이야.

GM 전자결재는 기존 지부장 서류의 결재대기와 현장 보고 열람을 구분해. 지부장 업무·결재는 기존 체크리스트·작성 서류와 현장 보고 수신함을 구분해. 현장 보고 메뉴는 공용 서류함의 초안·제출·반려·승인 상태 필터와 새 보고서 작성을 제공해.

관제 자료관리 목록은 검색·필터·행별 관리 버튼으로 구성해. 사건철에 다중 공개 체크박스를 두지 않아. 업로드 폼의 주버튼은 비공개 저장, 보고서의 주버튼은 지부장에게 제출, 지부장 수신함의 주버튼은 승인으로 명확히 나눠.

### 시안과 디자인 규칙

시안은 docs/m0/visuals의 7종이야. CONCEPTS.md에 그림별 목적·프롬프트·검토 메모를 남겨. 생성 이미지의 예시 본문과 날짜는 실제 데이터가 아니며, 브랜드 영문 정식 명칭·기존 사번·표시값은 실제 구현에서 원본을 사용해.

- 기준 배경은 #061018, 패널 #0c202b, 선 #22414b, 본문 #d8e6e8, 보조 #7f9ba2, 강조 #8dd2df, 주버튼 #5aa6bc야. 흰 공문은 #ffffff와 짙은 글자로 유지해.
- 한글은 맑은 고딕/Segoe UI 계열, 문서번호는 Consolas 계열을 사용해. 본문·입력·조작 글자는 14~16px, 주요 제목은 28~32px를 기준으로 맞춰.
- 시안마다 조금 다른 로고 크기·사이드바 폭·아이콘은 최종 화면 확정 때 한 규칙으로 통일해. 현재 시안은 구현과의 완전 일치가 검증된 최종 화면이 아니야.
- 데스크톱은 상단+사이드바+본문, 편집은 폼과 원문 미리보기, 결재는 흰 문서와 옆 결재 영역이야.
- 모바일은 메뉴를 접고 표의 핵심 열을 세로 목록으로 바꿔. 폼·미리보기·결재 패널은 한 열, 제출·저장 버튼은 내용과 겹치지 않게 배치해.
- 로그인은 역할을 코드로 판별하는 한 입력창이고 관제 접속은 별도 경로를 유지해. 역할·오류·연결 실패를 명확히 보여줘.
- 관제 개요는 현재 페이즈와 지부장 서류 승인대기·최근 작업을 요약하고 각 메뉴로 연결해. 임의 통계나 별도 기능을 추가하지 않아.
- 로딩·빈 목록·권한 없음·업로드 실패·동시 저장 충돌·저장 중 화면 이동 상태를 각각 설계해.

M5 검증: A·B·C 비공개 자료를 사건철에 연결하고 하나씩 공개해. 플레이어는 공개한 자료만 보고 숨겨진 자료 수는 알 수 없어야 해. 미리보기는 실제 역할 화면과 같고 열람·서명·저장 상태를 바꾸면 안 돼.
